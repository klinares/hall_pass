# Web build tests

Run from `world_tour_unity/` after a web build into `tour/`: `node Tests/Web/run.mjs`. It writes `Temp/web-results.json` (the evidence: per-test pass/fail, counts, numbers, warnings) and screenshots in `Temp/web-shots/`. Unity clears `Temp/` when the Editor quits, so copy anything you want to keep, or pass `--out` and `--shots`. It uses the Playwright already installed in `world_tour/tests/e2e/node_modules` and installs nothing. `server.mjs` is a plain static server (Content-Type and Content-Length only, like GitHub Pages); run it on its own with `node Tests/Web/server.mjs ../tour` to play the build locally.

- **cold_load_1366x768 / cold_load_1920x1080**: a fresh browser loads `tour/` and reaches `WT_BOOT_READY`, with no console or page errors and no requests outside the local server. The canvas fills the window with no scrollbars. Records bytes, the largest file and ms to ready, and takes a screenshot.
- **cached_reload**: a second visit transfers under 200 KB, because Unity's cache serves framework, data and wasm (this proves the template's cacheControl works on the real build).
- **storage_blocked**: with `indexedDB.open` and `localStorage` throwing, the game still starts with no console errors, reaches `WT_DATA_READY`, and logs `WT_SAVE_READY persistent=false` (it plays on an in-memory save).
- **broken_build**: a temp copy with the wasm deleted shows the lowercase failure message with one short detail line, not a blank page or Unity's banner.
- **size_budget**: the download must be under 20 MB (`--budget-mb`). Over 12 MB, or a cold load over 8 s, is recorded as a warning.
- **data_loads**: the cold load logs `WT_DATA_READY` with the week, word and skipped counts the Node validator gets from the served `StreamingAssets/weeks.json` (2 weeks, 22 words, 0 skipped today), the week that opens on the browser's local date, `config=ok`, no console errors, and `?v=` on both data requests.
- **weeks_edit_shows_on_reload**: on a temp copy, a week dated today (the browser's local date) is added at the top of `weeks.json` between two loads in the same browser context, and the second load reports one more week, with that week open (the cache-buster beats the cache).
- **weeks_broken_week_skipped**: on a temp copy with a broken week added at the top, the player reports `skipped=1`, still loads the other weeks, and logs a `[data]` warning but no console error.
- **local_date**: with the browser's Date pinned to 2026-11-21 03:30 UTC (`clock.setFixedTime`, so timers still run), the `today=` in `WT_DATA_READY` must be 2026-11-20 in America/New_York and 2026-11-21 in Pacific/Kiritimati, and equal to the page's own local date each time (`Plugins/WebGL/clock.jslib`). A game that read UTC would fail New York, at any time of day. The results file records the date the game used.
- **save_first_run**: a fresh browser logs `WT_SAVE_READY persistent=true fans=0 unlocked=1 v=1 recovered=false`, and `localStorage['worldtour.v1']` then holds JSON with `v: 1` and coffee unlocked.
- **save_survives_reload**: a save made by the web game's own `store.js` migrate (1234 lifetime fans, 2 venues) is put in `localStorage`, and after a reload the player reports `fans=1234 unlocked=2`, which proves the read path in the stripped player.
- **save_unreadable_backed_up**: with `{not json` stored, a reload reports `recovered=true`, keeps the text under `worldtour.v1.unreadable`, writes a fresh valid save, and logs no console error.
- **save_backup_fails_keeps_main**: with `{not json` stored and the write to `worldtour.v1.unreadable` refused (`QuotaExceededError` for that key only), the reload reports `persistent=false recovered=false`, the main key still holds `{not json`, and a `[save]` warning explains why.
- **start_card_enter / start_card_click** (task 2.2): a cold load reaches `WT_START_SHOWN` (Boot shows the click-to-start card once data and save are ready) with sound still locked. Then Enter (1366x768; the start button has keyboard focus) or a click on the start button (1920x1080) must log `WT_STARTED`, `WT_SOUND_UNLOCKED` and `WT_MAIN_READY` (Main loaded, first screen on the stack), plus `WT_SOUND_READY` or a `WT_SOUND_UNVERIFIED` warning (clips made; the check reads one back with GetData), with no console errors. Screenshots: `start_card_<size>.png` and `main_<size>.png`.
